# Hosted trust-control mapping

**Status:** Phase 0 implementation map  
**Last reviewed:** 2026-08-01

This table assigns every normative trust requirement to an existing automated
gate or a named delivery-phase owner. Role names become accountable people in
the release tracker before private beta.

| Control | Normative requirement                                                                                                                              | Current proof                                                                                                      | Delivery owner                                                             |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| COL-01  | C4 credentials, native payloads, repository snapshots, binaries, ignored files, and sensitive-trait inference MUST NOT be intentionally collected. | Strict upload DTO tests, scrubber seeded/clean corpus, collection category allowlist.                              | Ingestion owner; Phase 2 forbidden-payload storage test.                   |
| COL-02  | Collection MUST NOT serialize a native session and then attempt to scrub it.                                                                       | `IngestionBatchDraftSchema` represents normalized events only; `ScrubbedIngestionBatch` is created field-by-field. | CLI/collector owner; Phase 2 integration test.                             |
| COL-03  | Ingestion and artifact contracts MUST reject raw/native payloads, environment dumps, complete agent files, and repository snapshots.               | Zod strictness/raw-field tests; ADR 0004 artifact allowlist.                                                       | API and artifact owners; Phase 2 malicious-request suite.                  |
| CON-01  | Discovery MUST NOT enable collection.                                                                                                              | Consent schemas require an affirmative record and literal processing acknowledgements.                             | CLI owner; Phase 2 discovery-with-zero-upload test.                        |
| CON-02  | Consent MUST NOT be inferred from login, silence, bundled terms, MCP, or another installation.                                                     | Per-installation consent contract and frozen disclosure copy.                                                      | Identity/project owners; Phase 2 negative consent matrix.                  |
| CON-03  | Historical import MUST show agents, date range, count, bytes, policy, and likely redactions and require separate consent.                          | ADR 0006 migration boundary.                                                                                       | Migration owner; Phase 7 preview/confirmation test.                        |
| CON-04  | Revoked/disabled clients MUST NOT advance a checkpoint.                                                                                            | Canonical `consent_required` and `project_disabled` errors.                                                        | Ingestion owner; Phase 2 revocation transaction test.                      |
| AI-01   | Baton and subprocessors MUST NOT train shared models on customer content.                                                                          | Trust policy and ADR 0005 provider acceptance gate.                                                                | Product/privacy owner; provider contract register before first processing. |
| DEL-01  | Restores MUST apply deletion tombstones before serving traffic.                                                                                    | Retention workflow and ADR 0003.                                                                                   | Platform owner; Phase 7 restore drill.                                     |
| TEN-01  | Tenant identity MUST come from a verified credential and MUST NOT be selected by request data.                                                     | ADR 0003 repository boundary.                                                                                      | Identity/data owners; Phase 1 cross-tenant negative suite.                 |
| TEN-02  | Signed object URLs MUST be short-lived and tenant scoped.                                                                                          | ADR 0004 caps grants at 15 minutes.                                                                                | Artifact owner; Phase 2 cross-tenant/expiry tests.                         |
| NAT-01  | Upload and artifact DTOs MUST have no complete native-session field.                                                                               | Protocol strictness tests and branded scrubbed boundary.                                                           | Protocol owner; continuous CI.                                             |
| LOG-01  | Content, prompts, responses, secrets, diffs, and signed URLs MUST NOT enter logs/traces/analytics.                                                 | Canonical problem schema excludes stacks; trust policy.                                                            | Platform owner; Phase 1/2 canary log-capture tests.                        |
| ING-01  | Consent validation, idempotent insert, audit metadata, and checkpoint advance MUST be transactional.                                               | ADR 0003.                                                                                                          | Ingestion/data owners; Phase 2 fault-injection test.                       |
| ING-02  | Duplicate/out-of-order delivery MUST converge without overwrite and retries MUST NOT reveal another tenant.                                        | Checked-in convergence corpus.                                                                                     | Ingestion owner; Phase 2 two-device test.                                  |
| IR-01   | Incident response MUST support credential revocation, ingestion suspension, scoped deletion, provider escalation, and user notice.                 | Threat model actions and retention workflow.                                                                       | Security owner; pre-beta tabletop and runbook.                             |

No row may be marked release-complete from documentation alone when its proof
column assigns a later-phase acceptance test.
